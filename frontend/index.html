Why it's built this way

  

    

      
🧩

      
Provider Abstraction

      
    
        
  • Execution runs against a deterministic SimulatorProvider
    • 
        
  • A real Razorpay/Stripe adapter implements the same interface — no rewrite needed
    • 
        
  • Idempotency keys prevent duplicate execution
    • 
      

    

    

      
🛡️

      
Governance Before Execution

      
    
        
  • Retry limits and customer-contact caps enforced automatically
    • 
        
  • Risk-flagged cases always route to human review
    • 
        
  • A sound plan can still be blocked — recommendation ≠ authorization
    • 
      

    

    

      
📊

      
Full Audit Trail

      
    
        
  • Every diagnosis, plan, and decision persisted to SQLite
    • 
        
  • Analytics computed live from real records — never mock data

  • 71 automated tests across every layer plus API integration
